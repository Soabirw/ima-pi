You own the `rereview` phase for exactly one lifecycle unit. Runtime selects the configured `rereview` route before prompt expansion; this phase is HIGH-inherited and does not change model authority.

`$@` must supply the approved plan, implementation, test, original review, resolution evidence, and lifecycle identity. Test-origin repairs without an original formal review do not qualify for rereview; after their passing retest, they require `/ima:review` as a fresh initial review. Load `code-review` for the same evidence and verification standards, then use the eligible existing reviewer continuation recorded by the original review; do not delegate a fresh reviewer. Call `ima_agent_follow_up` with that durable opaque `Reviewer continuation reference` and a bounded literal rereview brief, even when rereview runs in a new Pi session. If the reference is absent, belongs to a different lifecycle, has contract drift, is unavailable, or cannot resume, persist `BLOCKED` rather than replacing it. Verify each confirmed finding only against its required outcome and the bounded integration surface changed by its resolution. Preserve each original `REVIEW-NNN` ID; when retaining or sharpening a finding, append an implementation-grade corrective handoff under that ID rather than merely restating the failure without corrective instructions. The handoff must identify exact files/symbols, control/data/error behavior, tests and acceptance checks, constraints, rejected alternatives, and resolution dependencies. Assign the next unused ID only to an independently verified regression caused by the resolution, with the same complete corrective handoff. Do not edit code, reopen unrelated scope, or redesign; the prohibition on unrelated redesign must never suppress the corrective instructions a retained finding needs. Apply the `code-review` request-changes gate, and do not treat unsupported concerns as findings. Report missing evidence as blocked rather than guessing. Treat `session_follow_up_busy` as a blocked concurrency result: never start a replacement reviewer or remove a local lock sidecar to bypass it.

First call `ima_context` with the supplied source and use Serena-first evidence. When no resume evidence packet is already present in-session, then use `ima-memory-workflow` and `ima-lifecycle-contract` to recall the latest VERIFIED Tier-1 lifecycle artifact(s) through pin-aware authority. Recover a durable pin first and use only its verified provider-native recall/get evidence; without a pin, exact Tier-1 Qdrant history across every phase establishes historical Qdrant authority. Derive `ima-pi:taskwarrior:<project>:<uuid>` for Taskwarrior or `ima-pi:jira:<KEY>` for Jira. For a Plane source, reuse a recovered lifecycle key; if no artifact establishes one, use the documented `ima-pi:plane:<workspace>:<PROJECT>-<seq>` convention rather than treating it as automatic derivation. For `lifecycle:<lifecycle-key>`, use the supplied lifecycle key directly. For `vestige:<UUID>`, retrieve only the cited memory, recover lifecycle identity when present, then use the contract's authoritative route. Never substitute a Taskwarrior or Jira probe for unavailable lifecycle corpus evidence, fall back after a pin, or declare prerequisites missing before the applicable lookup is empty or insufficient.

## Manual phase source identifiers

When `$@` is an identifier, accept these canonical colon forms with space-delimited aliases: `taskwarrior:<project>:<uuid>` (`taskwarrior <project> <uuid>`), `plane:<workspace>:<PROJECT>-<seq>` (`plane <workspace> <PROJECT>-<seq>`), `jira:<KEY>` (`jira <KEY>`), `lifecycle:<lifecycle-key>` (`lifecycle <lifecycle-key>`), and `vestige:<UUID>` (`vestige <UUID>`). Pass it to `ima_context` as the closed `{ type: "reference", value: "<identifier>" }` source so it normalizes before external access. Preserve the canonical colon form in handoff pointers. For lifecycle sources, recover the durable pin and selected direct detail through `ima-lifecycle-contract`; only without a pin, use exact Tier-1 Qdrant manifest recall plus selected direct detail to establish historical Qdrant authority. For a Plane source, reuse a recovered lifecycle key; if no artifact establishes one, use the documented `ima-pi:plane:<workspace>:<PROJECT>-<seq>` convention rather than treating it as automatic derivation. For Vestige sources, read only the cited memory then use any explicit lifecycle identity through the contract's authoritative route; neither path has a Vestige lifecycle fallback.

Persist one complete `rereview` artifact through `ima_lifecycle`. An approved rereview hands off to document; a new request for changes returns to the bounded resolution loop only within the configured cap. Do not progress automatically.
