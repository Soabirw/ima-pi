# FNR-3022 — Scorecard and adversarial review workflows

## Target disposition

| Goose source | Pi-native target |
| --- | --- |
| `scorecard` | `/ima:scorecard` |
| `adversarial-review` | `/ima:adversarial-review` |
| `adversarial-review-claude` | provider-neutral `adversary-a` |
| `adversarial-review-openai` | provider-neutral `adversary-b` |

The port removes Goose YAML/ETA recipes, fixed model pins, provider profiles, and `sub_recipes`. Pi prompts own judgment, declarative read-only agents own independent attack contracts, and `ima_delegate` provides existing bounded parallel execution.

## Entry points and boundaries

`/ima:scorecard` accepts one explicit target and reports evidence-backed A/B/C/D/F grades for Code Standards, Security, Test Coverage, Documentation, and Maintainability. It runs only existing non-mutating validators and is read-only initially. A later explicit README request may apply only the exact displayed `## Scorecard` section to one unambiguous README.

`/ima:adversarial-review` builds one evidence packet and delegates it in parallel to fresh `adversary-a` and `adversary-b` sessions. Both require exact configured `adversaryA`/`adversaryB` routes, catalog availability, and distinct `(provider, model)` identities. They have `review-read` authority, no nested delegation, and no session follow-up. The resulting report is advisory; `/ima:review` remains the formal lifecycle route and this workflow creates no `REVIEW-NNN` IDs or lifecycle state.

## Verification and limitations

Provider-free Node tests cover optional role parsing, exact routing, pair preflight, agent contracts, prompt contracts, and failed pre-spawn admission. Run `npm test`, `git diff --check`, and `npm pack --dry-run`. Manual Pi acceptance must confirm target clarification, no initial scorecard write, bounded later README mutation, missing/same-route blocks, two distinct live routes, same packet/fresh sessions, reconciliation and dropped claims, and no formal review persistence. Live provider behavior remains contingent on local provider access and quotas.

## Rollback

Remove these two prompts, two adversary definitions, optional roles, route-pair preflight, their focused tests, and documentation. Existing `HIGH`, `reviewVerify`, `/ima:review`, and general `ima_delegate` behavior remain unchanged.
