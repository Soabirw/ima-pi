## Brand, Copy, and Editorial Preservation

`ima-brand` retains the authoritative IMA identity, terminology, voice/tone, visual, and digital standards. `ima-copywriting` retains evidence-first, solution-oriented, independent, plain-language writing that treats the reader as an ally; its format, CTA, framework, transition, and prohibited-AI-tell guidance remains progressive-disclosure content.

The editorial scorecard retains Brand Voice, Evidence Quality, Audience Clarity, Structural Craft, and CTA Effectiveness, with letter grades, strengths, priority fixes, and line notes. It is not the engineering quality advisory command. The editorial workflow retains Plan → Write → Review → Approve → Learn and composes brand, copywriting, and editorial-scorecard skills. Learning is explicit and requires approval before persistence.

## Email Boundaries

The email skill preserves `assets/base-template.html`, newsletter, drip, transactional, CSS-safe, and EspoCRM references, with parser-safe wrapper serialization and self-contained-CSS-only Python helper behavior:

```bash
python3 skills/ima-email-creator/scripts/css-inliner.py INPUT.html [--out OUTPUT.html]
python3 skills/ima-email-creator/scripts/espocrm-prep.py INPUT.html [--out OUTPUT.html]
```

Without `--out`, helpers write to stdout. Their skill-local requirements are opt-in: use an isolated environment and `pip install -r skills/ima-email-creator/scripts/requirements.txt` only when a user chooses to run them. Nothing installs automatically. The EspoCRM helper uses parser-owned wrapper construction, which prevents its own style attribute serialization from creating markup but does not sanitize hostile child HTML. The CSS inliner rejects external stylesheet links and external CSS `@import`/`url(...)` references before it calls Premailer, and Premailer is denied network and external-file loading. Helpers do not send email, manage credentials or recipient data, fetch/upload/host remote assets, configure ESP analytics, or prove email-client rendering. Resolve `__SUBJECT__`, `__UTM_CAMPAIGN__`, and `__SECTION_IMAGE_URL__` before distribution; preserve EspoCRM single-brace tokens, use approved HTTPS hosts and meaningful alt text, and never include secrets, recipient IDs, or tokens in URLs. Use a user-selected path, a documented ignored project-local output path, or stdout; preview manually before distribution.

## Research Reuse

FNR-3023 remains the source of truth for the existing medical and patristic targets. Medical guidance uses `ima-research`, never silently substitutes `ima-knowledge`, applies PICO and current-primary-source verification, audits funding/conflicts, calibrates uncertainty, escalates emergencies, and does not diagnose, prescribe, dose, or direct medication changes. Patristic guidance covers AD 30–430 through Augustine, uses `theology` with `metadata.collection: fathers` and `metadata.era: patristic`, verifies quotations against primary pages, preserves chronology and attribution distinctions, avoids anachronism, and reports uncertainty plainly.

## Verification and Limitations

`tests/ima-content-research-skills.test.js` verifies new assets/frontmatter, local Markdown links, representative domain and safety contracts, opt-in helper interfaces, existing research mappings, and user-facing documentation. `npm test` executes the provider-free Node suite. These checks do not prove model adherence, live corpus/web availability, medical or historical correctness, email-client rendering, email delivery, or optional Python helper execution.

Manual Pi acceptance: run `pi -e .`, confirm the five new and two existing research skills appear, then request representative brand/copy routing, five-category editorial review, Plan → Write → Review → Approve → Learn guidance, email helper/setup guidance, and research safety/source handling. Python execution and client preview remain separately opt-in human checks.
