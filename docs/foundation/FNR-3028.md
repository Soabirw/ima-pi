# FNR-3028: JavaScript framework, browser, API, and testing skills

## Outcome

FNR-3028 packages seven top-level Pi skills: `js-fp-api`, `js-fp-react`, `js-fp-vue`, `js-fp-wordpress`, `jquery`, `playwright`, and `unit-testing`. Pi discovers them through the existing root `package.json` declaration, `pi.skills -> ./skills`; no loader, manifest change, dependency, or runtime implementation was added.

## Pi-native rationale

A Pi skill is discoverable guidance at `skills/<name>/SKILL.md`, exposed as `skill:<name>` and entered with `/skill:<name>`. It is not an agent, Goose subrecipe, or spawning unit. Agent and prompt skill lists may recommend a skill for routing, but do not prove automatic loading, model adherence, or child-session creation. Pi's existing delegation remains the agent-spawning boundary.

## Manual acceptance

Run `pi -e .`, verify each `/skill:<name>` entry in help/autocomplete, then request representative guidance for parameterized API validation, React hooks, Vue composables, WordPress AJAX/events, jQuery in a WordPress/Bootstrap page, Playwright accessibility/network/visual choices, and unit-versus-integration/E2E mocking decisions. This checks discovery and presentation only.

## Limitations

The root suite does not run a browser, framework application, database, WordPress, provider-backed semantic test, or external service. It does not prove a model loaded or followed skill content. Browser guidance must not duplicate deterministic unit coverage, and the skills contain no credentials or production payloads.

## Rollback

Remove the seven skill directories, `tests/javascript-testing-skills.test.js`, the seven discovery assertions, this document, and the README section. No package manifest, dependency, runtime, data, or sibling-repository rollback is required.
