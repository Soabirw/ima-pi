# FNR-3020 — Bounded advisory workflows

FNR-3020 ports exploration, architecture, investigation, instruction, and prompt-starting outcomes into Pi-native package resources without copying Goose recipe mechanics. Sources are Jira FNR-3020, Taskwarrior `0e20101e-b50b-4a65-809d-338cbfb01319`, lifecycle `ima-pi:taskwarrior:FNR-3007:0e20101e-b50b-4a65-809d-338cbfb01319`, requirements memory `5f27af6e-7a24-4f27-91ca-254892765234`, and approved plan `25f81cbd-01cb-40bd-8914-b6ceb75859b6`.

## Source-to-target disposition

| Source workflow | Pi-native target | Entry point |
|---|---|---|
| `explore` | Existing LOW, read-only specialist agent | `ima_delegate` with `agent: "explore"` |
| `architect` | In-session advisory prompt | `/ima:architect [source]` |
| `investigate` | Evidence-led diagnostic prompt | `/ima:investigate [source]` |
| `instructor` | Context-aware teaching prompt | `/ima:instruct [source]` |
| `prompt-starter` | Inline prompt-building prompt | `/ima:prompt-start [rough-context]` |

`explore` remains an agent because its narrow repository evidence contract benefits from isolated LOW-tier context and restricted read tools. The other four workflows remain current-session prompts because they require direct synthesis, clarification, or teaching rather than a separate execution role. `/ima:prompt` remains the package discovery probe; it is not replaced by `/ima:prompt-start`.

## Authority boundaries

| Workflow | Permitted outcome | Non-mutating boundary |
|---|---|---|
| `explore` | Targeted repository findings, files, and blockers | Read-only tools; no edits or nested delegation |
| `architect` | Evidence-oriented recommendation, simpler path, trade-offs, boundaries, risks | No implementation, edits, tests, builds, branches, commits, or phase chaining |
| `investigate` | Reproduction status, evidence trace, proven root cause or ranked hypotheses | No fixes, formatting, dependencies, migrations, state changes, branches, commits, or ticket writes |
| `instruct` | Safe teaching with evidence, command-risk labels, prerequisites, and success signals | Never runs the operational work or persists externally |
| `prompt-start` | One inline, standalone, ready-to-paste prompt | No execution, GUI editor, file draft, background process, or automatic persistence |

All five are optional advisory operations. They do not become stages in the formal `plan -> implement -> test -> review -> document` lifecycle and stop without implementing.

## Pi integration

Pi discovers the four prompts from the existing `package.json` `pi.prompts` directory. `ima_context` provides normalized Serena-first source assembly. `ima_delegate` owns bounded agent spawning and configured model routing. `explore` supplies narrow repository evidence, while `vision-handoff` exclusively interprets visual sources for investigation or instruction. The current session owns clarification and synthesis.

Tier labels express judgment or routing intent only; prompts do not claim to change the active session model. Existing extension APIs, agent schemas, model routing, lifecycle behavior, and resource precedence remain unchanged.

## Adapted and removed Goose assumptions

- No recipe YAML, ETA, profile/model pinning, `sub_recipes`, workflow DSL, or implicit phase chaining.
- No one-to-one requirement that every source recipe become a command.
- No GUI prompt editor, filesystem draft, template directory, or background process ownership.
- No new extension, dependency, router, persistence mechanism, or permission framework.
- Delegation uses the existing `ima_delegate` contract rather than inventing a payload shape.

Confirm `git status --short` has no unexpected effects. Provider or credential limitations must be reported rather than bypassed.

## Limitations and rollback

Prompt contracts guide model behavior but cannot replace runtime safety enforcement. Deep diagnostics still require the user to approve expensive, noisy, runtime-sensitive, or ambiguously safe probes. Visual and delegated acceptance depends on configured providers and external services.

The change is additive. Roll back by removing the four prompt files and their focused tests and documentation. Retain the existing `explore` agent, `/ima:prompt` probe, integrations, model configuration, and delegation runtime; no data, credential, dependency, or migration rollback is required.
