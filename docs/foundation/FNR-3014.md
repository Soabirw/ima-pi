# FNR-3014 — First-Class Agents and Adaptive Delegation

## Sources and outcome

This foundation follows Jira FNR-3014, Taskwarrior `08de19ef-8c5f-4a2a-96b7-a4c35d7dd430`, and approved Vestige plan `a197e043-ea30-42b7-89c3-648cb11554ee`. It adds a bounded production agent layer rather than turning the FNR-3009–FNR-3012 technical probes into an orchestration framework.

The verified SKYNET-242 extension is sourced at `plane:ima:SKYNET-242`, lifecycle `ima-pi:plane:ima:SKYNET-242`, with original root `527df7f4-593d-585d-80b7-0b14c05e22cb`. It adds an optional parent-minted, assignment-scoped typed verification capability for trusted single implementation/tester assignments; it does not add a generic command runner.

## Architecture

- `lib/ima-agents.ts` parses constrained YAML frontmatter, validates definitions, derives source paths, and resolves whole-document project → user → package replacements.
- `lib/ima-delegation.ts` is the pure core for request validation, self-contained briefs, exact model routing, authority, disjoint write scopes, retry decisions, immutable state, sanitization, session reuse eligibility, and typed-verification request admission.
- `lib/ima-delegated-verification.ts` validates and snapshots admitted manifest scripts, revalidates them before execution, projects fixed package-manager argv, bounds/redacts output, and owns timeout/cancellation settlement handling.
- `lib/ima-agent-continuation.ts` removes `test` from every focused continuation, so persisted session records never carry parent-minted verification snapshots.
- `extensions/agents.ts` is the Pi SDK shell. It registers model-callable `ima_delegate` plus `/ima:agents`, `/ima:agent-sessions`, and `/ima:agent-follow-up`; it creates the typed `test` tool only from admitted snapshots and passes command plus argv to Pi without a shell.
- `agents/` contains the current seventeen package-defined specialists rather than the original seven-agent set.

## General runtime safeguards

The extension loads trusted definitions and explicit model configuration, validates every assignment before creating a child, uses the configured exact provider/model, and reports runtime session identity. It accepts one to four assignments, runs only disjoint work concurrently, records sanitized in-memory session metadata, and returns structured failures without exposing credentials or transcripts. Every fresh or focused-continuation terminal result uses a 400-semantic-line/10 KiB UTF-8 bounded summary plus `session: { id, file, resumeReference }`; the complete authored report remains only in the child Pi JSONL session. The complete `ima_delegate` payload is compact valid JSON within Pi’s 2,000-line/50 KiB ceiling, including serialization overhead. The pure routing contract rejects unavailable HIGH/vision capability rather than substituting a lower tier.

## Typed verification model and runtime safeguards

An optional assignment `verifications` list has one to four closed entries containing only an ID, `npm` or Composer runner, repository-contained cwd, manifest script, preapproved arguments, and timeout. Admission requires all of the following: exactly one assignment, a trusted project, a resolved agent with `write` or `test-write` authority that declares `test`, unique valid IDs, safe relative paths, non-symlink containment, a regular selected manifest, and a declared valid script. The parent snapshots the manifest identity/content and selected script, then revalidates all of it immediately before execution.

The child receives a typed `test` tool only when snapshots are admitted and may pass only `{ id }`. The parent fixes `npm run <script> -- <args>` or `composer run-script <script> -- <args>` argv without a shell. Install/update, arbitrary executable or command, environment, URL, and credential fields are not expressible. No admitted entry means no typed `test` tool.

Verification shares the assignment mutation queue with scoped native writes and edits. The parent selects the `1,000`–`360,000` ms timeout. Timeout or cancellation immediately latches coordinator-visible unsafe state; later assignment effects are blocked, retries and reuse are prevented, and the coordinator observes executor settlement for at most `1,000` ms. If settlement is not observed, it reports cleanup-unverified rather than false settlement; a late rejection remains observed. This bounded observation does not assert process or descendant termination.

Both result channels sanitize stdout/stderr before the 200-line/16 KiB tail bound. Redaction covers supported structured sensitive fields and complete supported authorization-header values before truncation; it is not universal secret detection. Focused continuations never receive typed test authority.

## Configuration and authority classification

Verification IDs, runner/script/cwd/argument metadata, and the parent-selected timeout are **non-secret variables**; the timeout is a parent-owned runtime capability value. Provider credentials are **secrets**. Continuation/session records and provider-pin state are **local-only values**. This capability introduces no **platform binding**.

## Live acceptance and limitations

Provider-free coverage does not claim live provider acceptance. This capability is not an OS sandbox: an admitted trusted manifest script retains its host filesystem and network authority. Timeout/cancellation requests executor cancellation and bounds settlement observation only; it neither proves process/descendant termination nor turns a cleanup-unverified result into a settled one. Supported output redaction is defense in depth, not a claim of universal secret detection. This document makes no deployment, release, or tracker-completion claim.

## Compatibility and migration

Existing assignments without `verifications` retain prior behavior and expose no typed `test` tool. There is no persisted verification grant or snapshot to migrate; continuations retain their existing local-only session policy but always lose typed test authority. The guarded provider-free `test` script and `verify:package-dry-run` are package metadata only. Virtual timing is confined to BookStack integration/migration fakes; production pacing is not replaced. No provider migration, external persistence migration, or live acceptance run is implied.

## Rollback

The FNR-3014 foundation remains additive: reverting its original agent layer requires a coordinated restoration of its prior agent/docs/dependency state. SKYNET-242 is opt-in per parent assignment, so omitting `verifications` disables typed delegated verification for that assignment. A capability rollback must change the library, extension, tests, and documentation together; it must not treat continuation/session data as a recoverable verification grant. No data migration, external update, deployment, release, or tracker rollback is required or implied.
