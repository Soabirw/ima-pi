# FNR-3014 — First-Class Agents and Adaptive Delegation

## Sources and outcome

This implementation follows Jira FNR-3014, Taskwarrior `08de19ef-8c5f-4a2a-96b7-a4c35d7dd430`, and approved Vestige plan `a197e043-ea30-42b7-89c3-648cb11554ee`. It adds a bounded production agent layer rather than turning the existing FNR-3009–FNR-3012 technical probes into an orchestration framework.

## Architecture

- `lib/ima-agents.ts` parses constrained YAML frontmatter, validates definitions, derives source paths, and resolves whole-document project → user → package replacements.
- `lib/ima-delegation.ts` is the pure core for request validation, self-contained briefs, exact model routing, authority, disjoint write scopes, retry decisions, immutable state, sanitization, and session reuse eligibility.
- `extensions/agents.ts` is the Pi SDK shell. It registers model-callable `ima_delegate` plus `/ima:agents`, `/ima:agent-sessions`, and `/ima:agent-follow-up`.
- `agents/` contains exactly seven initial specialists.

## Runtime safeguards

The extension loads trusted definitions and explicit model configuration, validates every assignment before creating a child, uses the configured exact provider/model, and reports runtime session identity. It accepts one to four assignments, runs only disjoint work concurrently, records sanitized in-memory session metadata, and returns structured failures without exposing credentials or transcripts. Every fresh or focused-continuation terminal result uses a 400-semantic-line/10 KiB UTF-8 bounded summary plus `session: { id, file, resumeReference }`; the complete authored report remains only in the child Pi JSONL session. The complete `ima_delegate` payload is compact valid JSON within Pi’s 2,000-line/50 KiB ceiling, including serialization overhead. The pure routing contract rejects unavailable HIGH/vision capability rather than substituting a lower tier.

Adapter-boundary tests additionally cover injected child spawning, concurrent ordering and cancellation, one-retry execution, terminal/observed-identity validation, bounded success/failure/continuation results, mechanically scoped write ownership, and fail-closed bash redirect classification. ## Live acceptance and limitations

Live acceptance requires a configured profile and provider credentials. Use `pi -e .`, then `/ima:agents`; invoke `ima_delegate` with exact complete assignments; and inspect `/ima:agent-sessions`. Verify configured LOW/MID/HIGH/vision identity, disjoint concurrent writes in disposable scope, one safe retry, unavailable-model failure, fresh reviewer identity, focused continuation, and vision evidence routing. These live operations were not claimed by deterministic tests because credentials and provider availability are environment-dependent.

Rollback is additive: remove the production agent files, restore the placeholder docs, and remove the direct `yaml` dependency. Existing probes remain unchanged.
