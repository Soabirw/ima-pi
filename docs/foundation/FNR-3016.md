# FNR-3016 — IMA Gateway-Service Integration

## Sources and approved outcome

This implementation follows Jira FNR-3016, Taskwarrior `689fa7ac-84b7-42d0-8912-b8ef76041370`, lifecycle `ima-pi:taskwarrior:FNR-3007:689fa7ac-84b7-42d0-8912-b8ef76041370`, and approved Vestige plan `bbdc0465-711f-4f91-b128-4c6fe85f4a19`.

It adds two narrow model-callable production tools: `ima_context` assembles Serena-first phase context, and `ima_lifecycle` persists and semantically verifies a complete lifecycle artifact. The tools retain Serena, Vestige, Qdrant, Jira, and Taskwarrior as external service boundaries; they do not create a workflow engine or service SDK.

## Architecture and contracts

- `lib/ima-context.ts` is the pure schema-version-1 source-validation, source-normalization, Serena-state evaluation, context-derivation, and sanitization core.
- `lib/ima-lifecycle.ts` is the pure lifecycle request/artifact/nonce/receipt/recall/result core. Recall succeeds only when **one** result contains all required markers; storage-node shape is intentionally ignored.
- `extensions/integrations.ts` is the thin Pi shell. It owns injected process/filesystem effects, bounded project files, the direct Vestige MCP persistence boundary, and registrations for `ima_context` and `ima_lifecycle`.

`ima_context` accepts exactly one source: Jira key, Taskwarrior project + UUID, root-contained regular file, Vestige memory ID, or bounded free text. It optionally performs a read-only `ima-mcp qdrant find`. It returns a single versioned `PhaseContext`, including source content/references, explicit Serena memory state, bounded durable references, and sanitized diagnostics.

Its public Pi tool schema names every source and durable-knowledge field, mirrors the pure validator's bounds, and rejects unknown properties instead of exposing `Type.Any()`. The source uses five closed raw-JSON-Schema `oneOf` branches with singleton `StringEnum` discriminators, rather than `Type.Union`, `Type.Literal`, or `const`; each branch requires only its selected source fields. `prepareContextArguments` projects valid requests canonically and replaces invalid input with a static sentinel before Pi's generic validation, while `validateContextRequest` remains runtime authority and direct invalid requests return a non-echoing corrective hint.

### Context-contract hardening

The completed feature-level hardening keeps public and runtime validation aligned: mixed or unknown source fields and durable-knowledge fields are refused, the Vestige ID requires the canonical 8-4-4-4-12 hexadecimal UUID shape, and invalid requests never cross an external boundary. The direct `@earendil-works/pi-ai` runtime dependency supplies the installed `StringEnum` and provider-serialization helpers used to prove the modern and legacy Google schema forms.

Model-facing output is also bounded and sanitized consistently: direct-text title metadata, file-derived keys/titles/references, durable-reference summaries, and unknown source failures cannot reflect assignment-like sensitive values. Ordinary metadata remains unchanged. A requested Qdrant `durableKnowledge.limit` bounds returned references, and Jira hydration consumes the installed helper's normalized `descriptionText`, falling back safely to its trimmed `summary`.

The original approved flow wrote lifecycle metadata and a correlation nonce to an agent-owned temporary file, invoked high-level `ima-mcp vestige save`, then searched by lifecycle key and nonce. That temporary-file and CLI flow is superseded for formal lifecycle persistence. Current `ima_lifecycle` builds the metadata and nonce in memory, calls direct Vestige MCP `smart_ingest` once, validates the receipt, then calls direct `recall` by lifecycle key and nonce. Save success without a matching nonce, identity, phase, and completed outcome remains a failure because ingestion may have occurred but is not verified; it never retries the save. This formal persistence path does not require the `ima-mcp` binary.

## Serena ordering and source boundaries

The context coordinator resolves trusted project root, then always runs:

1. `ima-mcp serena project activate --json`
2. `ima-mcp serena instructions --json`
3. `ima-mcp serena memory list --json`
4. reads each present standard memory: `core`, `conventions`, `tech_stack`, `suggested_commands`, and `task_completion`
5. hydrates the selected source, then optional Qdrant lookup.

Any activation, instructions, listing, or source-hydration failure is failed context. Missing standard memories are explicit degraded context; optional Qdrant failure is also degraded and never loses source context.

Jira calls the installed Atlassian helper only; Taskwarrior runs narrow read-only export; Vestige source uses `vestige get`; free text is never reinterpreted; and files must be regular, non-binary, <=256 KiB, root-contained after realpath resolution. No tool mutates Jira or Taskwarrior, indexes/mutates Qdrant, or absorbs IMA RAG ownership.

## Security and privacy

The shell uses argument arrays, fixed output/process limits, untrusted-JSON parsing, injected dependencies, and bounded result mapping. File paths cannot traverse or escape through symlinks. The original CLI flow used agent-generated temporary artifact paths; current lifecycle persistence sends the bounded artifact through the configured direct Vestige MCP child instead. Outputs redact sensitive assignment-like values and never return raw stderr, credentials, authorization headers, environment dumps, transcripts, or full service payloads. Invalid prepared calls use a static sentinel, and unknown source exceptions collapse to a safe boundary code rather than reflecting error text. The lifecycle nonce is correlation evidence, not a credential.

## Live acceptance and limitations

Live service acceptance requires the locally configured external gateways and the installed Atlassian skill. Use a model session loaded through `pi -e .`, call `ima_context` for FNR-3016 through Taskwarrior, Jira, `README.md`, lifecycle root `7027acec-43d3-4fa4-83ec-16e993551720`, and bounded free text; optionally make one read-only Qdrant query. Verify the consistent schema and Serena-first order.

For `ima_lifecycle`, explicitly authorize one meaningful, labeled non-production decision artifact with a unique test lifecycle key, then verify the direct `smart_ingest` receipt plus semantic `recall`. A prior non-interactive `/ima:plan` probe observed `ima_context` activity without the original invalid-request symptom but did not complete within 300 seconds; it is non-terminal evidence only. Do not claim external uptime, terminal/provider behavior, or physical Vestige node shape from deterministic tests. The tool does not implement `/ima:cycle` or production phase prompts; later stories own them.
