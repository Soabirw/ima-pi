## Command surface

```text
/ima:cycle start [--review-cap 0-10] [--implementation generic|js|wp] [--mode guided|autonomous] <source>
/ima:cycle status
/ima:cycle reply <answer>
/ima:cycle stop [--ack]
/ima:cycle resume [--autonomous|--guided|--mode guided|autonomous]
/ima:cycle close [--commit-prep]
```

Accepted sources are one Jira key or supported Jira browse URL, one exact `taskwarrior <project> <uuid>` pair, `plane:<workspace>:<PROJECT>-<seq>`, `plane <workspace> <PROJECT>-<seq>`, or `https://<plane-host>/<workspace>/browse/<PROJECT>-<seq>`. A Plane browse URL normalizes to the canonical Plane source, while configured `PLANE_BASE_URL` remains the API destination. A Story is the lifecycle unit; checklists do not create independent cycles.

New cycles default to `generic` implementation mode. Explicit `generic`, `js`, and `wp` implementation modes select `/ima:implement`, `/ima:implement-js`, and `/ima:implement-wp` respectively; all use the configured `implement` route. The implementation selection persists in cycle state. Legacy schema-v1 state without `implementationMode` normalizes to `js`; an explicitly present invalid implementation mode is rejected.

Cycle mode is a separate persisted `guided | autonomous` field. New and legacy-missing cycle modes normalize to `guided`. A guided start keeps plan approval human-gated. `start --mode autonomous` marks the plan packet `autonomousPlan: true`; the plan agent self-approves only one bounded, conflict-free, low-risk delivery unit with no unresolved product, architecture, security, rollout, or verification questions, otherwise it persists `plan BLOCKED` and stops (recommending `/ima:decompose` for multiple delivery units). `resume --autonomous` upgrades a guided cycle, and `resume --guided` downgrades it; `resume` without a mode intent preserves the durable setting. New cycles use a review cap of five; existing caches preserve their explicit cap.

## SKYNET-192 parent-host orchestration

`/ima:cycle` is a parent orchestrator rather than a phase worker. On `start` and `resume`, it selects configured `commands.cycle`, otherwise configured `HIGH`, otherwise the current parent route. An explicit configured route that is unavailable or unauthenticated blocks rather than falling through.

Each phase runs in an isolated native Pi host session with lifecycle tools and context and may delegate bounded specialist leaves. The only extension excluded from a phase host is the package cycle coordinator; safety and user extensions remain loaded. A phase first resolves its direct dispatched command and then its legacy phase mapping. If still unmapped, `resolution` (`resolve-review`) falls back to `implement`, `rereview` falls back to `review`, and every other unmapped phase inherits the orchestrator route. A configured route that is unavailable or unauthenticated blocks; only an absent mapping may use a fallback.

When a phase host needs operator input, the coordinator posts the bounded phase output as a persistent cycle message with the exact reply command; a transient notification is only a fallback if transcript delivery fails. `/ima:cycle reply <answer>` sends the literal answer, including line breaks, only to the current waiting phase host. It neither supplies accepted lifecycle evidence nor advances a phase. `stop` persists state before aborting the active phase host. After restart, recovery validates the retained host session, project, and lifecycle context, reconciles evidence, and requires explicit `resume`; it never auto-progresses. Manual confirmed `close` remains required.

Successful cycle-owned specialist session records persist in ignored local `.ima-cycle/agent-sessions.json`; follow-up-eligible direct/manual specialist records persist in `.ima-cycle/direct-agent-sessions.json`. Both survive isolated Pi sessions. Rereview invokes `ima_agent_follow_up` for an eligible original reviewer continuation and never starts a new reviewer. `commands.cycle` is the sole cycle-specific configuration mapping and uses the normal command-mapping form; profile mappings are non-secret configuration, provider credentials are secrets, and `.ima-cycle` records are local-only.

### Continuation durability and local-lock addendum

Cycle references remain bound to their persisted cycle owner; direct/manual references may be restored across sessions only from `.ima-cycle/direct-agent-sessions.json`. Registry updates use an exclusive local sidecar `.<target-name>.ima-agent.lock` beside each registry, retrying bounded contention 40 times at 10 ms and returning `cycle_agent_session_busy` or `direct_agent_session_busy` when still occupied. A focused continuation acquires its own adjacent sidecar before `SessionManager.open`; an occupied lease returns `session_follow_up_busy`. The session lease remains through settlement, durable record update, and disposal; after verified cleanup, it releases only when its token and filesystem node still match. Unverified child cleanup returns `session_cleanup_unverified`, retains the lease, and blocks retry. Locks are **local-only values**, contain no credentials or session content, are never stolen as stale, and must not be deleted blindly; an operator may clean one up only after confirming no live owner. This addendum records current integrated behavior, not a final rereview verdict.

## Fixed lifecycle and user gates

`/ima:cycle` coordinates only this fixed lifecycle:

```text
plan -> implement -> test -> review -> resolution/rereview when requested -> document -> close

Before the first review, `test DEFECTS` returns to plan-bound `implement` repair and then `test` again; only a subsequent `PASSED` enters a fresh initial review.
```

It is not a generic workflow engine or configurable graph. Starting opens a `plan` phase host only when no eligible manual plan exists. For an exact source-bound lifecycle, cycle automatically adopts the unique newest verified manual `plan APPROVED` record and begins at `implementation`; a newer `plan BLOCKED`, ambiguous, malformed, unavailable, or saturated plan history fails closed. A verified older plan without a canonical plan outcome marker requires one explicit TUI review and confirmation of the exact immutable artifact, then a reference-only approval receipt and recheck before adoption. Adoption never changes cycle mode, bypasses review caps or blockers, or auto-closes a tracker. Imported approval pointers are revalidated before implementation/recovery, and later lifecycle evidence must carry the selected approval lineage. A guided start keeps the plan human-gated and waits for explicit `resume` after accepted phase evidence. An autonomous start lets the plan agent self-approve only through the fail-safe `autonomousPlan` directive; otherwise it persists `plan BLOCKED` and stops. After an approved autonomous plan, normal phase dispatch reuses the autonomous tail only while verified lifecycle evidence leaves the state `awaiting-resume`; pre-review `test DEFECTS` therefore dispatches implementation repair and retest within the existing dispatch ceiling. It stops on BLOCKED, unresolved outcome, review-cap excess, or dispatch-ceiling warning. `status` only reports state. `stop` first persists active state, then pauses the cycle and requests Pi abort of the active phase host; `--ack` is required when stopping a write-capable guided phase, while autonomous stop aborts the tail without acknowledgement. `resume` explicitly dispatches the current allowed phase in guided mode. When a phase persisted an explicit `BLOCKED` outcome and its external blocker is later corrected, guided `resume` may retry that same phase while preserving the blocked evidence. Test defects route to implementation repair and retest; an exact legacy state with phase `test`, status `blocked`, sole blocker `test:DEFECTS`, and latest `test/DEFECTS` evidence recovers at implementation. Review-cap, invalid-transition, and post-tracker-close blocks remain terminal and cannot be bypassed by `resume`.

A review `REQUEST_CHANGES` enters `resolution` only within the configured cap, `RESOLVED` enters `rereview`, and review/rereview approval enters `document`. A document `READY` outcome makes the cycle closeout-ready; it never closes a tracker by itself. Normal `close` requires TUI confirmation and mutates exactly the selected source tracker. A Plane close rereads the exact item and workflow states, accepts only `backlog`, `unstarted`, or `started` as the current group, requires exactly one `completed`-group state, verifies the exact state-mutation receipt, and never retries a completed tracker mutation. `close --commit-prep` performs only read-only Git status and diff checks.

### Document evidence and historical closeout compatibility

New documentation evidence persists as phase `document`; `closeout` remains a separate human-authorized terminal phase and is never relabeled. Exact Qdrant schema-v1/v2 verification, source identity, lifecycle key, and prior-artifact lineage are required for document recall and hydration. A historical immutable `closeout` record may satisfy document recovery only when it passes that full verification, carries one exact terminal standalone `phase=document` `READY` or `BLOCKED` marker outside Markdown fences and quotes, is not a final-closeout artifact, and is the deterministic unambiguous newest eligible record. Its required lineage must include the consumed evidence and respect approved-plan ordering. Ordinary closeout evidence is ignored after verification rather than treated as documentation. Missing, corrupt, incomplete, malformed, competing, ambiguous, forged, wrong-source, wrong-lineage, or unclear-newest candidates fail closed.

## Safety, persistence, and Phase 1 durability

For every phase, including `document`, the coordinator selects and validates phase-host routing before host prompt expansion/injection. Lifecycle evidence is accepted only when project, lifecycle, source, expected phase, receipt, and semantic recall all match and the submitted artifact contains exactly one canonical outcome marker.

Cycle intent/configuration and the last-known phase persist in project-local `.ima-cycle/active.json`; successful cycle-owned specialist session records persist in `.ima-cycle/agent-sessions.json`, and follow-up-eligible direct/manual records persist in `.ima-cycle/direct-agent-sessions.json`. The folder creates its own `.ima-cycle/.gitignore` containing `*`, never changes the repository-root `.gitignore`, and keeps all local-only records ignored. Profile mappings are non-secret configuration; credentials are secrets and neither record stores them. `active.json` is a validated cache; verified Tier-1 Qdrant lifecycle artifacts remain the authoritative phase truth.

A provisional `awaiting-evidence` snapshot with a unique phase-dispatch record persists before phase-host prompt expansion or injection. The parent buffers matching child lifecycle results and advances only after the host ends safely. Host startup or terminal failure leaves the provisional state for reconcile-first recovery; it never creates a guessed next phase.

On `session_start` and `status`, recovery reconciles verified lifecycle artifacts before reporting. Before an explicit `resume` reopens a retained phase host, it validates the host session, project, and lifecycle context. It never auto-progresses a phase. A missing or corrupt cache falls back safely to the branch cache or a fresh source-derived lifecycle key. A stale cache is corrected by verified lifecycle evidence, so `/ima:new` and a fresh terminal do not create a no-cycle-running ghost.

### Root-cause mapping and deferrals

- RC1: persist-before-host prevents a phase dispatch from orphaning cycle state.
- RC2: `.ima-cycle/active.json` restores cross-session intent; reconciliation corrects it from verified Tier-1 Qdrant evidence.
- RC3: implementation, test, review, resolution, and rereview prompts recall the latest verified lifecycle artifact by canonical lifecycle key when no resume packet is present.
- Concurrent cycles, new store types, and a standalone CLI remain deferred. The delivered autonomous plan gate and tail remain bounded by verified evidence, the fixed reducer, review cap, dispatch ceiling, interruption, and no-auto-close.

Before close, closeout evidence is revalidated. The coordinator performs one confirmed tracker mutation, then persists lifecycle closeout evidence. Those external writes cannot be atomic: if tracker mutation succeeds but lifecycle persistence fails, the state is `blocked-after-tracker-close` and the tracker mutation is never retried automatically.
