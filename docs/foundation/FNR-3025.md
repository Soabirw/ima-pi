## Memory routing and approval

`/ima:memorize` routes stable project facts to the smallest Serena standard memory and cross-project preferences to Vestige. It asks one focused question only for material project/global ambiguity. It rejects secrets, logs, transcripts, lifecycle state (use `ima_lifecycle`), and durable reference knowledge (use Qdrant). It reads/searches first, presents exact wording and duplicate/conflict disposition, waits for explicit approval, performs one supported gateway write, and verifies it. It never performs an automatic mutation.

## Preflight evidence and child boundary

Preflight scopes are `offline`, `quick`, and `full`; statuses are PASS, WARN, FAIL, BLOCKED, SKIP, and NOT_CONFIGURED. Serena and Vestige remain gateway-brokered integrations: healthy gateway evidence is not degraded merely because direct registration reports `configured:false`. Story A supersedes the Qdrant MCP probe: quick/full calls package-native read-only `ima_corpus_status` once, never discovers Qdrant through `mcp`, and offline reports the live Qdrant/Ollama check as `SKIP`. Native status `ready` is PASS; unavailable/incompatible prerequisites are WARN when optional and FAIL when explicitly required. Missing Qdrant MCP registration is expected; a missing native corpus tool is FAIL. Status never bootstraps or mutates the corpus.

Potentially large raw gateway output is placed in unique restrictive `/tmp` evidence directories, inspected only in bounded chunks, redacted in the final report, and cleaned on every terminal path. A requested redacted report may remain at `/tmp/ima-pi-preflight-<timestamp>.md`; raw evidence must not remain. Cleanup failure is reported with the path.

The parent sends one complete read-only assignment to `preflight-probe` through `ima_delegate`. The child must return exact marker `IMA_PI_PREFLIGHT_CHILD_OK` and identify itself as the package agent. It does not inspect resources and is not a general diagnostic substitute.

## Migration safety

Migration classifies legacy entries rather than blindly converts them. Serena and Vestige remain external package-MCP service boundaries; Qdrant corpus support is Pi-native through `ima_corpus_*` tools. `ima_context` uses package-owned direct MCP sessions for Serena and Vestige, plus its package-native Qdrant/Ollama durable-knowledge boundary, while `/ima:cycle` reconciliation uses configured direct Vestige `recall`. Migration never direct-registers Serena or Vestige and never adds/copies user or project `qdrant-memory`/`qdrant-mcp` MCP entries; legacy Qdrant MCP entries are unsupported/obsolete or manual cleanup. No Qdrant endpoint, model, collection, credential, Goose YAML/ETA, service-SDK assumption, or secret is copied. Only `~/.pi/agent/ima/config.json` or trusted `.pi/ima/config.json` are eligible destinations. Invalid JSON, unsafe/untrusted paths, unknown roles, and unavailable model decisions are refused. The exact redacted preview and explicit approval precede an atomic same-directory temporary-file-and-rename update, then existing config validation reports effective configuration.

## Verification and limitations

Deterministic coverage is static prompt contracts, package-agent parser/catalog checks, Pi package discovery checks, `npm test`, and `git diff --check`. Human acceptance still validates model adherence, configured gateways, real child spawning, large-output cleanup under abnormal termination, semantic preference merge behavior, and real approved configuration migration. No provider availability is claimed without direct evidence.

## Rollback

Existing integrations, lifecycle tooling, and `ima_delegate` remain unchanged. Approved external memory/config writes are separately reversible by their recorded preview and verification evidence.
