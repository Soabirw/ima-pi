# FNR-3019 — Quality and learning workflows

FNR-3019 adds four Pi-discoverable terminal commands: `/ima:test`, `/ima:review`, `/ima:review-verify`, and `/ima:document`. They preserve separate testing, independent review, narrow verification, and documentation/learning roles without adding cycle automation or a workflow DSL.

`/ima:test` uses the repository-supported smallest test level and confines mutation to named tests and explicit test support. Production defects receive stable `TEST-NNN` evidence and return through plan-bound implementation repair and retest before a fresh initial review. `/ima:review` requires the latest ordered evidence to end with implementation completed followed by test passed; test-origin repairs do not make that review a rereview. It starts a fresh product-read-only reviewer and requires a separately fresh verifier pass for every Critical or Warning candidate before assigning `REVIEW-NNN`. `reviewVerify` is optional: an absent mapping visibly falls back to fresh `HIGH`; an explicitly configured unavailable mapping fails closed.

`/ima:review-verify` reads one file range plus at most one dependency hop and emits only `CONFIRMED`, `WITHDRAWN`, or `PARTIAL` with one reason. It cannot edit or propose remediation. `/ima:document` delegates only exact local Markdown/text documentation files to `documenter`; paths must be explicitly named, while directories and production/test/config/migration/release targets are rejected. The documenter can only prepare an external-update manifest. Parent commands retain optional external persistence and mandatory `ima_lifecycle` authority.

Stable instructions route to Serena, evolving lifecycle outcomes to Vestige, durable references to Qdrant, and concise work status to Jira/Taskwarrior when separately approved. Raw telemetry, credentials, transcripts, and debugging noise are never lifecycle learning.

Provider-free tests cover agent parsing, discovery, routing fallback, exact documentation scope validation, prompt contracts (including the pre-review test-defect loop), and existing delegation safeguards. Human acceptance still requires configured Pi providers and external services; deterministic tests do not prove provider adherence or service uptime.
