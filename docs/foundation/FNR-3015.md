# FNR-3015 — Visible Activity, Cancellation, Failure Reporting, and Focused Safety

## Sources and approved outcome

This implementation follows Jira FNR-3015, Taskwarrior `59fc5211-53d3-486b-b725-e9ec76903af4`, lifecycle `ima-pi:jira:FNR-3015`, and approved Vestige plan `a83c13a7-e220-425e-9a5d-801df469ccf9`. It makes the production `ima_delegate` tool understandable and controllable without exposing raw event streams or adding confirmation fatigue.

FNR-3014 remains the authoritative delegation layer. FNR-3015 adds a presentation and reporting projection; it does not replace routing, authority, retry, ownership, session reuse, or cleanup decisions.

## Architecture

- `lib/ima-activity.ts` is a pure, schema-version-1 activity core. It creates immutable request-order topology, reduces sanitized events with terminal-monotonic state, classifies tool activity into stable categories, renders at most five lines, and builds deterministic terminal reports.
- `lib/ima-delegation.ts` remains authoritative for request validation, exact model routing, recovery, ownership, terminal completion, and reuse eligibility.
- `extensions/agents.ts` remains the impure Pi shell. It observes child sessions, emits numeric-timestamp activity events, handles aborts, and projects snapshots through Pi's tool-update callback and TUI APIs.
- The FNR-3010 control probe remains removable spike evidence. Production code neither imports from nor redesigns it.

Activity is a projection, not a second workflow engine. Child phases come from each resolved agent's declared result kind.

## Live surfaces

Every observed snapshot can be sent through Pi's `onUpdate` callback as a bounded partial tool result. In TUI mode, the same snapshot replaces one `ima-delegation` widget and one status entry. The widget preserves assignment order and shows:

- delegation title/reference and overall state;
- child phase, agent, exact routed provider/model/thinking when known;
- declared skills, explicitly labeled as declarations rather than proof of semantic use;
- sanitized tool or gateway category;
- child state, elapsed time, attempt/retry, and escalation marker.

The projection does not retain prompts, transcripts, command strings, paths, arguments, tool output, credentials, or provider payloads. Tool-update and TUI failures are caught independently. Projection degradation is reported as a boolean and cannot change child execution. Widget and status entries are cleared in `finally` on success, failure, cancellation, validation/setup failure, or exception.

## Cancellation and stopped-state reports

A tool abort first emits `cancelling` for each nonterminal assignment and only then aborts live sessions. Already successful children remain successful. Future work stops. A cancelled writing assignment reports its declared repository-relative write scope as a **possible** partial-write scope; cancellation never claims rollback or proof that every possible write occurred.

Terminal schema-version-1 reports include:

- phase, overall state, elapsed time, and projection degradation;
- each child state, attempts, blocker, retry history, escalation, and resume reference;
- completed assignment IDs;
- possible write scopes and unsafe assignment IDs;
- reusable successful session references;
- one deterministic safe-next-action code and text.

Only a successful session whose agent allows follow-up receives a resume reference. Failed, blocked, and cancelled children always report `null`.

Safe-next-action mappings distinguish partial-state inspection, safety-boundary correction, exact-model/auth restoration, provider recovery, agent-contract correction, human decisions, and successful parent synthesis. Reported scopes are structured data; no shell command is generated from an untrusted path.

## Focused safety boundary

FNR-3015 does not add a permission matrix or interactive confirmation loop. It surfaces only the existing FNR-3014 mechanical boundary:

- repository-relative writer ownership;
- realpath/symlink containment;
- scoped `write`, `edit`, and narrow `bash` operations;
- fail-closed ambiguous shell classification;
- unsafe sibling abort and cleanup.

An observed unsafe or failed mutating operation emits the stable `safety:intercepted` category and a stopped-state report without displaying the attempted command or path. Ordinary allowed work remains non-interactive.

## Privacy and limitations

The activity projection stores only stable categories and bounded labels. Declared skills are configuration facts, not evidence of semantic use. Provider/session retention outside this extension remains governed by Pi and the provider. Very fast intermediate events may be visually skipped, but the final immutable activity snapshot and outcome report remain authoritative.

## Rollback

This change is additive and has no data, dependency, or configuration migration. Rollback removes `lib/ima-activity.ts`, reverts coordinator/projection instrumentation in `extensions/agents.ts`, removes the activity tests and adapter additions, and reverts FNR-3015 documentation. FNR-3014 delegation and the standalone probes continue to operate.
