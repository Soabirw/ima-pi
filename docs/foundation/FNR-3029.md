# FNR-3029: WordPress, PHP integration, and IMA site-building skills

## Outcome

FNR-3029 packages seven top-level Pi skills: `php-fp-wordpress`, `phpunit-wp`, `wp-ddev`, `ima-bootstrap`, `livecanvas`, `ima-forms-expert`, and `php-authnet`. Pi discovers them through the existing root `package.json` declaration, `pi.skills -> ./skills`; no loader, package-manifest change, dependency, extension, or runtime implementation was added.

## Pi-native rationale

A Pi skill is discoverable guidance at `skills/<name>/SKILL.md`, exposed as `skill:<name>` and entered with `/skill:<name>`. It is not an agent, Goose subrecipe, or spawning unit. Discovery proves a package resource exists; it does not prove automatic loading or model adherence.

## Explicit dispositions and security boundaries

`wp-ddev` is the supported local WordPress environment. `wp-local`/LocalWP is deprecated and not packaged in this task; that does not prohibit a future separately approved restoration. The standalone `ima-brand` skill remains owned by FNR-3031; `ima-bootstrap` retains only its packaged implementation reference.

The skills preserve independent capability checks and nonce verification; type-appropriate sanitization, validation, late context-specific escaping, and prepared SQL; DDEV inspection/backups/dry runs before destructive work; LiveCanvas query/global-state safety; server-authoritative IMA Forms validation; and Authorize.Net sandbox-first, PCI/tokenization, redaction, constant-time webhook signature, idempotency, and explicit-production-intent boundaries.

## Limitations
