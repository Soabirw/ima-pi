# FNR-3032 — MCP, browser, research, and work-management integration skills

## Approved outcome and source coverage

FNR-3032 originally ported ten integration skills into the Pi package, including `mcp-qdrant`. Story A supersedes that Qdrant MCP adapter with the package-native `ima-qdrant` skill and `ima_corpus_*` tools. The remaining brokered integration skills are `mcp-serena`, `mcp-vestige`, `mcp-atlassian`, `mcp-taskwarrior`, `mcp-context7`, `mcp-tavily`, `mcp-fetch`, `mcp-sequential-thinking`, and `mcp-chrome-devtools`. Source assets are the corresponding canonical `ima-goose/skills/` trees. `mcp-serena/scripts/migrate-context-to-serena.py`, `mcp-atlassian/scripts/atlassian-api.mjs`, and `mcp-taskwarrior/agents/openai.yaml` are retained as package support assets.

## Pi-native runtime

`extensions/mcp.ts` is a thin composition root around pinned `pi-mcp-adapter@2.17.0`, the latest release permitted by this repository's npm publication-age policy during implementation. `config/mcp.json` supplies lazy direct MCP defaults for Serena, Vestige, Context7, Tavily, Fetch, Sequential Thinking, and Chrome DevTools. Story A removes the Qdrant MCP default: native `extensions/institutional-memory.ts` communicates directly with Qdrant and Ollama through bounded Node `fetch`. The adapter loads its package config path while preserving shared user and project MCP configuration merge/override behavior.

Atlassian remains on the packaged REST helper; it is not a default MCP server. Plane is also a packaged direct REST helper rather than a brokered MCP integration. Taskwarrior remains on its native CLI; it is not an MCP server. `ima_context` uses package-owned direct MCP sessions for Serena bootstrap and Vestige source retrieval, while its optional durable-knowledge contract uses the package-native Qdrant/Ollama boundary. Formal `ima_lifecycle` persistence calls direct Vestige MCP `smart_ingest` and verifies receipt plus nonce, identity, phase, and outcome through `recall`; it does not require `ima-mcp`. `/ima:cycle` reconciliation uses configured direct Vestige `recall`; parent gateway and delegation effects use configured direct MCP, while bounded child sessions use the package compact `mcp` tool.

## Direct self-hosted Plane REST helper

`/skill:plane-api` adds a separate, package-owned direct REST surface for one explicitly configured self-hosted Plane instance. It requires the non-secret `PLANE_BASE_URL` variable and secret `PLANE_API_KEY` in the invoking environment, sends the token only through `X-API-Key`, rejects Plane Cloud and unsafe base URLs, rejects every HTTP redirect rather than replaying an authenticated request, and registers no MCP server or credential file. The bounded surface reads one canonical work item, its project states, and its comments; its writes are explicit work-item creation through one project-identifier-resolved POST, plain-text comment creation, and a state-only update after fresh item/state reads.

Focused automated verification is credential-free and uses injected fetch:

```bash
node --test tests/plane-api.test.js
```

Live reads are opt-in in a fresh shell with operator-provided environment variables; never paste their values into a command history, document, prompt, or log:

```bash
node skills/plane-api/scripts/plane-api.mjs plane:get plane:<workspace>:PROJ-123
node skills/plane-api/scripts/plane-api.mjs plane:states plane:<workspace>:PROJ-123
node skills/plane-api/scripts/plane-api.mjs plane:comments plane:<workspace>:PROJ-123
```

Live mutations require an explicit selected creation, comment, or state action. For temporary state changes, capture the original state, reread the selected item afterward, and restore it when appropriate. Rollback removes only `skills/plane-api/`, `tests/plane-api.test.js`, the Plane additions to integration/discovery tests, the Plane-driven inventory assertion in `tests/code-walkthrough.test.js`, and the corresponding README and foundation documentation entries. Revert that inventory assertion from 57 to 56 with the Plane skill removal; rollback does not change an external Plane instance or any MCP configuration.

## Installation and updates

### Team or global installation

Install the package from the approved unpinned private Gitea source:

```bash
pi install ssh://git@gitea.theflccc.org:2222/IMA/ima-pi.git
```

This command was verified in an isolated Pi home on 2026-08-03: Pi exited successfully, recorded the package in its isolated settings, installed runtime dependencies, and exposed the package resources. Update explicitly with `pi update --extensions` or `pi update --all`; updates are never background or unattended.

### Local development

For a checkout used in local development:

```bash
pi install /home/eric/IMA/dev/ima-pi
npm run install:skills -- --validate
npm run install:skills
```

The installer copies package skills to `~/.agents/skills` by default. Use `node scripts/install.ts --dest <isolated-directory>` for validation. It preserves unrelated skills and atomically replaces only same-named package targets; it never edits Pi settings, MCP configuration, profiles, or credentials.

## Prerequisites and limits

Node 24+, Pi, `npx`, and `uvx` are required. Serena JetBrains navigation needs the Serena plugin and a running IDE. Vestige and Chrome server executables/configuration remain external brokered services. Qdrant and Ollama are package-native corpus prerequisites checked by `ima_corpus_status`; no Qdrant MCP executable is required. `TAVILY_API_KEY` stays in the environment. Atlassian authentication stays in its existing environment variables. Missing executables, credentials, or corpus prerequisites should affect only the invoked capability.

Direct MCP skills use proxy discovery/calls; they do not claim generated SDK behavior. Direct Vestige ingestion does not replace the established lifecycle receipt protocol. No package config contains credentials.
