# FNR-3027: Core architecture, FP, search, and source-control skills

## Outcome

FNR-3027 packages ten top-level Pi skills: `architect`, `functional-programmer`, `js-fp`, `php-fp`, `py-fp`, `ruby-fp`, `rg`, `ima-git`, `gh-cli`, and `tea-gitea`. Pi discovers them through the existing `package.json` `pi.skills -> ./skills` resource declaration; no loader, extension, dependency, or custom discovery logic was added.

## Pi-native rationale

Pi natively discovers each `skills/<name>/SKILL.md` as `skill:<name>`. This preserves package/user/project precedence owned by Pi and keeps the port additive. Harness-neutral source material was copied from `ima-goose` without broad rewriting.

## Ruby missing-reference investigation and repair

The `ruby-fp` source linked `references/patterns.md` and `references/security.md`, but bounded searches of `~/IMA/dev`, distribution copies, tracked files, and relevant Git history found no tracked copies. They are not recovered source. This task adds narrowly scoped Ruby-native repairs for lazy evaluation, composition, currying, memoization, immutable pipelines, callable dependencies, SQL binds, argument-vector shell execution, validation, paths, safe parsing, secrets, and output/error boundaries.

## Manual acceptance

Run `pi -e .`, verify all ten skills appear in help/autocomplete, and request representative architecture, core/shell, language FP, `rg`, GitHub/Gitea, release-policy, and Ruby-reference guidance. This confirms interactive presentation only; static tests do not prove model adherence, external CLI authentication, services, or execution of the PHP/Python/Ruby examples.

## Limitations

No external CLI, provider, PHP, Python, or Ruby runtime is executed by the root suite. `ima-git` provides release preparation policy, not deployment authority. Skill documents never contain credentials.
