## Security and phase boundaries

JS work preserves Node 24+ native/current dependencies, pure business logic with explicit I/O edges, input validation, and parameterized SQL. Visual evidence routes to `vision-handoff`.

WordPress is a primary production route. State-changing or privileged work requires nonce verification and separate capability checks; boundary input is sanitized/validated; output is escaped for exact context; dynamic SQL uses `$wpdb->prepare()` or an equivalent parameterized API; and WordPress APIs/hooks are preferred. Established IMA plugin decoupling remains actions/filters rather than direct coupling. Visual artifacts require `vision-handoff`.

Prompts perform only immediate existing verification, adding tests only when the approved plan requires them. They persist verified `implementation` artifacts through `ima_lifecycle`, stop, and point to `/ima:test` (or explicitly justified `/ima:review`). Formal test/review entry and workflow chaining remain external.
