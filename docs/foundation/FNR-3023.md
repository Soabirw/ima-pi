# FNR-3023: Medical and Patristic Research Workflows

## Outcome

FNR-3023 ports two source-disciplined specialist workflows into `ima-pi` as Pi-native Markdown prompts plus reusable package skills:

| Source workflow | Pi entry point | Package skill |
| --- | --- | --- |
| `ima-researcher` | `/ima:medical-research [question]` | `ima-medical-research` |
| `patristic-researcher` | `/ima:patristic-research [question]` | `patristic-researcher` |

The implementation preserves behavior outcomes rather than Goose recipes, ETA templates, profile/model configuration, parameters, or lifecycle mechanics. Both commands accept natural-language questions, infer audience/depth when safe, ask only focused questions when consequential ambiguity remains, wait for empty input, and stop after research.

## Medical Mapping

The medical prompt and skill preserve an Honest Medicine™ patient-centered posture, PICO framing, current primary-source verification, the `ima-research` corpus, explicit no-`ima-knowledge` fallback, source and study-quality audits, funding/conflict review, calibrated uncertainty, emergency escalation, and no-diagnosis/no-prescribing boundaries. Patient-facing research includes the approved educational disclaimer.

The package does not add web search, Qdrant ingestion, corpus adapters, persistence, providers, dependencies, or medical decision software. Corpus availability and current-source access remain external effect boundaries and must be disclosed when unavailable.

## Patristic Mapping

The patristic prompt and skill preserve the AD 30–430 boundary through Augustine (with explicit later-reception exceptions), `theology` corpus guidance, `metadata.collection: fathers` and `metadata.era: patristic` preference, primary-source quotation verification, precise citations, chronology and historical context, authority distinctions, anti-anachronism, and honest uncertainty.

Five source indexes are packaged verbatim from `ima-goose/skills/patristic-researcher/references/`: quick reference, NT epistles, Apostolic Fathers, Ante-Nicene, and Nicene/Post-Nicene. Retrieval chunks remain discovery evidence—not exact quotations—until checked against primary repositories.

## Pi Rationale and Source Coverage

Prompts provide the interactive command contract; skills supply reusable domain instructions and indexes. Small intentional repetition prevents a new runtime abstraction. No agent, extension, parameter parser, workflow DSL, model router, executable research engine, or sibling-repository runtime dependency was introduced.

Automated Node semantic tests cover frontmatter, command discovery/provenance, skills, key source/safety/corpus contracts, no parameter grammar, and terminal workflow boundaries. They do not prove external corpus availability, live web verification, clinical/patristic correctness, or model adherence.

## Manual Acceptance and Limitations

Use Pi to exercise empty, specific, and ambiguous questions. Verify medical emergency handling, patient/clinician inference, missing-corpus disclosure, evidence audit, uncertainty, and disclaimer. Verify patristic index selection, metadata preference, primary-page quotation checks, precise citations, consensus/attribution distinctions, retrospective terminology, and uncertainty. External source or corpus outages must be reported, never hidden.

## Rollback

This is additive and migration-free. Remove the two prompts, two skills (including packaged references), test assertions, this document, and README entries. No dependency, data, service, or external-system rollback is needed.
