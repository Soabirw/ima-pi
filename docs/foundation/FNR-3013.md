# FNR-3013: Pi-native package, configuration, and resource foundation

Sources: Jira FNR-3013; Taskwarrior `FNR-3007` / `80f7e0f3-edd7-4ff9-bed2-9f5d0fa97951`; lifecycle `ima-pi:taskwarrior:FNR-3007:80f7e0f3-edd7-4ff9-bed2-9f5d0fa97951`; approved plan `eebb34d1-2dae-4ee3-aed0-0c888492dffb`.

Pi continues to own extensions, skills, prompts, settings, credentials, providers, and model catalogs through the unchanged package manifest. IMA-owned homes are `agents/`, `policies/`, and `config/`; `lib/ima-config.ts` contains deterministic configuration and named-resource precedence only. FNR-3014 owns agent schema, discovery, spawning, retries, fallbacks, escalation, and session routing.

Configuration paths, trust, roles, precedence, full-role replacement, explicit vision behavior, catalog validation, and secret rejection are documented in [`config/README.md`](../../config/README.md). The loader is read-only, takes all paths and trust explicitly, and makes no network, credential, or Pi-global access.

## Coverage, limits, rollback

Provider-free Node tests cover validation, immutable merge and provenance, named-resource precedence, catalog/image capability, paths, and project trust. `npm pack --dry-run` verifies package inclusion. Preset identifiers can drift with Pi catalogs; runtime catalog validation makes this explicit. Roll back by removing the additive FNR-3013 directories/files and README additions; no user/project configuration is created or migrated.
