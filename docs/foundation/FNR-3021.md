# FNR-3021 — Visual analysis, UI/UX review, and design-to-code

## Delivered boundaries

`ima_delegate` now accepts one to four absolute, accessible local images only for the `vision-handoff` agent. Admission is signature-based (PNG, JPEG, WebP, GIF), capped at 20 MiB per image, rejects duplicates and blocks the whole assignment on any invalid source. It sends Pi-native attachments only to the exact configured vision model. Briefs and projected results retain opaque IDs, basenames, MIME type, and byte size—not full paths, raw bytes, base64, or provider payloads.

`/ima:ui-ux-review` is read-only. It consumes configured external Chrome DevTools MCP evidence where available and keeps browser/DOM, keyboard, viewport, console/network, and visual-model evidence distinct. It never creates browser infrastructure; FNR-3032 remains responsible for transferable browser/MCP skill packaging.

`/ima:design-to-code` creates one approved WordPress/Bootstrap plan, persists it as `plan`, and stops at `/ima:implement-wp`. It does not implement, test, review, or run a pipeline.

## Limitations and verification

Screenshots cannot prove semantic accessibility, keyboard reachability, DOM relationships, screen-reader output, or live announcements. Pi session files or providers can retain attachments; no ephemeral-deletion claim is made. Provider-free tests cover admission, authority, Pi attachment options, sanitization, agent contracts, and prompt boundaries. Real configured vision and Chrome DevTools MCP behavior requires manual acceptance.
