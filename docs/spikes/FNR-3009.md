# FNR-3009: Pi child delegation primitives

## Decision

Use Pi's public SDK directly for bounded child delegation. The technical-spike command is:

```text
/ima:delegate-probe start <provider>/<model>
/ima:delegate-probe follow-up <provider>/<model> <absolute-session-file>
```

The spike does **not** implement the production agent schema, model tiers, orchestration, parallel UI, cancellation policy, retry policy, or lifecycle ownership. Those remain owned by later stories.

## Source and approved outcome

- Jira: FNR-3009, “Prove child agents, independent models, authority, and reusable sessions”
- Parent epic: FNR-3007
- Lifecycle: `ima-pi:jira:FNR-3009`

The intended proof is that a Pi parent can create a child on an independently selected provider/model, grant it a bounded tool allowlist without per-command prompts, reopen the exact persisted child session for a context-dependent follow-up, and return sanitized structured evidence rather than trusting child prose.

## Tested Pi contract

The spike uses public Pi SDK primitives: exact `ModelRuntime` lookup, `createAgentSession`, persistent `SessionManager` creation/opening, session tool-event subscription, prompt/idle completion, actual model/session identity, and disposal. No nested `pi` subprocess is used. SDK sessions execute their allowed tools without Pi's interactive per-command permission loop; project-resource trust remains separate.

## Functional boundary

### Pure core

`extensions/delegation-probe.ts` exports deterministic helpers for selector/command parsing, actual-model normalization, fixed brief construction, nonce extraction, sanitized tool-category classification, authority/continuity evaluation, independent-routing evaluation, and error sanitization. These helpers have no filesystem, network, model, session, or process side effects.

### Imperative shell

The command handler owns temporary workspace/session creation, fixed seed/marker I/O, exact model lookup/authentication checks, SDK child creation/reopening/disposal, event subscription, prompting, fixed HTTPS research, package-owned Serena bootstrap, optional structured-result output, and concise UI notification.

## Bounded authority proof

The start child receives only `read`, `write`, `bash`, and the package-owned `ima_serena_bootstrap` tool. Its fixed brief requires these harmless actions in order:

1. read a generated seed file;
2. write a marker containing the exact continuity nonce;
3. run `pwd`;
4. fetch one fixed HTTPS documentation URL with a 20-second timeout; and
5. invoke `ima_serena_bootstrap` exactly once with an empty object.

The child is explicitly forbidden from direct Serena MCP calls. The bootstrap tool is package-owned: it fixes the delegated checkout internally, discovers and validates Serena capability on its own MCP connection, requires instructions-first preparation when private session state is required, and accepts success only after exact checkout activation verification. The child receives neither the checkout value nor private Serena session state, and its isolated runtime excludes caller context, skills, prompts, themes, and unrelated extensions.

The result retains only semantic tool categories, booleans, actual model/session identity, a session reference, and concise stable errors. It never retains credentials, environment values, raw commands, raw network/MCP output, private session state, checkout configuration, or full transcripts. This proves explicit tool selection and non-interactive execution when all signals pass; it does **not** claim OS-level sandboxing or live Serena-service acceptance.

## Automated verification

The default suite is provider-free and makes no paid-model or live Serena call. Recorded verification covers parser behavior, nested model IDs, fixed briefs/boundaries, tool classification, fail-closed authority/continuity evaluation, error sanitization, package command discovery, rejection of missing/unsafe package bootstrap configuration, and hidden private bootstrap state. The recorded full suite result is 1,456 passing tests, zero failures, and four unchanged opt-in skips; `git diff --check` passed.

## Live cross-provider acceptance

Live cross-provider proof remains a separately authorized human operation. It requires an authenticated parent/child route, external HTTPS availability, and a configured Serena platform binding. A successful run must show the requested actual child identity, distinct routing where requested, all required authority categories, verified marker, a persisted session, and a follow-up with the same child session/model, recalled nonce, and zero rerun tool calls.

The recorded historical attempt did not complete because the configured child-provider account lacked credits. No bounded authority or continuity proof was accepted from that attempt, and no provider/model fallback or same-provider substitution was attempted. It remains insufficient for live acceptance.

## Human TUI acceptance

Open Pi with an authenticated parent route and run the bounded start command, then its follow-up using the returned session reference. Confirm command discovery, concise notifications, no per-command prompts, the fixed package-owned Serena bootstrap boundary, an understandable session reference, and a usable terminal. Rich child-activity rendering is deferred to FNR-3010.

## Temporary workspace cleanup

The start result returns a workspace/session reference for follow-up and inspection. The command preserves it after success or failure. After evidence is recorded, the human operator may remove that returned temporary workspace; the command never deletes user-supplied paths.

## Source-to-target coverage

| Source behavior | Pi-native target |
|---|---|
| Isolated child | `createAgentSession()` |
| Generated child provider/model settings | Explicit resolved `Model` |
| Child tool authority | Explicit child tool allowlist |
| Non-interactive child execution | SDK session without interactive tool approvals |
| Reusable context | Persistent `SessionManager` + `SessionManager.open()` |
| Serena integration authority | Fixed package-owned `ima_serena_bootstrap` tool |
| Private session/checkout containment | Isolated child runtime and package-owned bootstrap |
| Parent synthesis | Structured result from extension command |
| Production agent schema/orchestration | Deferred to FNR-3014 and FNR-3010 |

## Limitations and explicit deferrals

- Provider authentication, model availability, model compliance, external HTTPS, Serena configuration, and real MCP behavior are live-environment concerns.
- A child may fail a step; event and filesystem evidence fail closed and preserve only bounded partial evidence.
- There is no fallback model, reconnect, or substitute bootstrap path.
- The result schema is versioned spike evidence, not a production compatibility promise.
- Production agent discovery/schema, HIGH/MID/LOW routing, orchestration, retry/escalation, session-role tracking, parallel activity UI, cancellation, safety hooks, and lifecycle authority remain separately owned.
