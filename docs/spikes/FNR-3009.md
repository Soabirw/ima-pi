# FNR-3009: Pi child delegation primitives

## Decision

Use Pi's public SDK directly for bounded child delegation. The technical-spike command is:

```text
/ima:delegate-probe start <provider>/<model>
/ima:delegate-probe follow-up <provider>/<model> <absolute-session-file>
```

The spike deliberately does **not** implement the production agent schema, model tiers, orchestration, parallel UI, cancellation, retry policy, or lifecycle integration. Those remain owned by later stories.

## Source and approved outcome

- Jira: FNR-3009, “Prove child agents, independent models, authority, and reusable sessions”
- Parent epic: FNR-3007
- Approved plan: Vestige `33135a6e-28d1-4d71-b447-89d5763a7896`
- Lifecycle: `ima-pi:jira:FNR-3009`

The approved outcome is executable evidence that a Pi parent can:

1. create a child on an independently selected provider/model;
2. give the child a bounded tool allowlist without interactive per-command prompts;
3. persist and reopen the exact child session for a context-dependent follow-up; and
4. return sanitized, structured evidence instead of trusting child prose.

## Tested Pi contract

Implemented against pinned `@earendil-works/pi-coding-agent` **0.82.1**. The relevant public primitives are:

- `ModelRuntime.create()` and exact `getModel(provider, id)` lookup;
- `createAgentSession({ cwd, model, modelRuntime, tools, sessionManager })`;
- explicit built-in tool allowlist `tools: ["read", "write", "bash"]`;
- `SessionManager.create(cwd, sessionDir)` for persistence;
- `SessionManager.open(sessionFile)` for exact-session reopening;
- `AgentSession.subscribe()` for tool event evidence;
- `prompt()`, `waitForIdle()`, `getLastAssistantText()`, and `dispose()`;
- actual `session.model`, `session.sessionId`, and `session.sessionFile` identity.

No nested `pi` subprocess is used. SDK sessions execute tool calls without the interactive permission loop, while Pi's project-resource trust remains a separate concern.

## Functional boundary

### Pure core

`extensions/delegation-probe.ts` exports deterministic helpers for:

- selector and command parsing;
- actual model identity normalization;
- start and follow-up brief construction;
- nonce extraction from retained session text;
- sanitized tool-category classification;
- authority and continuity evaluation;
- independent-routing and error sanitization.

These helpers have no filesystem, network, model, session, or process side effects and are covered by provider-free `node:test` tests.

### Imperative shell

The command handler and two probe flows own:

- temporary workspace/session creation;
- fixed seed/marker file I/O;
- exact model lookup and authentication checks;
- SDK child creation/reopening/disposal;
- event subscription and prompting;
- fixed child HTTPS and read-only Serena operations;
- optional structured-result output and concise UI notification.

## Bounded authority proof

The start child receives exactly `read`, `write`, and `bash`. Its self-contained brief requires these fixed harmless actions:

1. read a generated seed file with Pi `read`;
2. write a marker containing the exact continuity nonce with Pi `write`;
3. run `pwd` with Pi `bash`;
4. fetch `https://github.com/earendil-works/pi` using `curl` with a 20-second timeout;
5. run the fixed read-only integration command:

   ```bash
   ima-mcp serena project status --project /home/eric/IMA/dev/ima-pi --json
   ```

The result stores only semantic tool categories, booleans, actual model/session identity, workspace/session paths, and concise stable errors. It never stores credentials, environment values, full commands, raw integration/network output, or complete transcripts.

This proves explicit tool selection and non-interactive execution. It does **not** claim OS-level sandboxing.

## Live cross-provider acceptance

The approved proof uses an Anthropic parent and exact OpenAI child with no fallback:

```bash
cd /home/eric/IMA/dev/ima-pi
IMA_PI_DELEGATION_RESULT=/tmp/fnr-3009-start.json \
  pi --provider anthropic \
     --model claude-sonnet-4-6 \
     --no-session \
     -e . \
     -p "/ima:delegate-probe start openai/gpt-5.4-mini"
```

Expected structured evidence:

- parent: `anthropic/claude-sonnet-4-6`;
- child: `openai/gpt-5.4-mini` from the actual `session.model`;
- provider and model differ;
- absolute child session file and session ID are present;
- file-read, file-write, shell, research, integration, and marker signals are all true;
- no per-command approval prompt appears;
- `status` is `passed`.

Then reopen the exact session file returned above:

```bash
IMA_PI_DELEGATION_RESULT=/tmp/fnr-3009-follow-up.json \
  pi --provider anthropic \
     --model claude-sonnet-4-6 \
     --no-session \
     -e . \
     -p "/ima:delegate-probe follow-up openai/gpt-5.4-mini <absolute-session-file>"
```

Expected: same child session ID/file, exact requested model, nonce recalled from retained conversation context, authority categories recalled, zero follow-up tool calls, and `status: passed`.

### Recorded live evidence

Run on 2026-07-30 with the exact commands above:

- Parent identity observed: `anthropic/claude-sonnet-4-6`.
- Actual child identity observed from `session.model`: `openai/gpt-5.4-mini`.
- Independent routing: `providerDiffers: true`, `modelDiffers: true`.
- Persisted child session ID: `019fb4fe-d266-7e90-b3df-63db04c6456e`.
- Persisted absolute session file: `/tmp/ima-pi-delegation-nsJMDC/sessions/2026-07-30T21-47-06-726Z_019fb4fe-d266-7e90-b3df-63db04c6456e.jsonl`.
- Start result: `failed` / `child_execution_failed`; the OpenAI provider returned an error before child completion because the configured account had no remaining API credits.
- Start authority evidence: no tool calls occurred, all authority booleans were false, and no marker was written. Therefore bounded authority was **not** claimed.
- Follow-up reopening evidence: same session ID `true`, same session file `true`, exact child model `true`, no follow-up tool calls `true`.
- Follow-up completion: blocked by the same provider credit error, so nonce recall was false and full continuity was **not** claimed.
- No provider/model fallback or same-provider substitution was attempted.
- No interactive permission prompts appeared during either SDK child run; because no child tool call reached execution, this alone is not accepted as authority proof.
- Workspace/session were preserved for inspection and retry after OpenAI credits are restored.

The deterministic suite passed independently of provider availability. Full acceptance still requires rerunning the same start and follow-up commands after OpenAI API credits are available, obtaining all authority booleans and nonce recall as true.

## Temporary workspace cleanup

The start result returns `workspace`. The workspace and persisted child session are intentionally preserved after both success and failure so the follow-up can run and partial evidence is inspectable. After evidence is recorded, the human operator may remove that returned temporary workspace. The command never deletes user-supplied paths.

## Limitations and explicit deferrals

- Provider authentication, model availability, model compliance, external HTTPS, and local `ima-mcp` availability remain live-environment concerns.
- A child may fail a step; event and filesystem evidence fail closed and preserve partial evidence.
- This spike has no fallback model. Missing model or auth is reported explicitly.
- The result schema is versioned spike evidence, not a production compatibility promise.
- Production agent discovery/schema, HIGH/MID/LOW routing, orchestration, retry/escalation, session-role tracking, parallel activity UI, cancellation, safety hooks, and complete gateway/lifecycle integration are explicitly deferred to FNR-3010, FNR-3011, and FNR-3014.
