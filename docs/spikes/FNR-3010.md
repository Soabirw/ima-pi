# FNR-3010 — Parallel Control and Safety Spike

Lifecycle: `ima-pi:jira:FNR-3010`. This removable technical spike tests Pi-native primitives, not production orchestration.

## Entry point

```text
/ima:control-probe start <provider/model> <provider/model>
/ima:control-probe cancel <run-id> <a|b>
```

`start` creates two isolated SDK child sessions, returns terminal control immediately, and reports only sanitized categories/states through one replaceable widget and status line. `cancel` selects an exact run and child, waits for `AgentSession.abort()`, and reports `cancelled-clean`, `cancelled-partial`, `completed-before-cancel`, or `cancel-failed`. Cancellation stops future work; it does **not** roll back effects.

## Design and evidence

The extension uses pure parser, reducer, state, command-classifier, cancellation, skill-observation, renderer, and sanitizer helpers. The shell owns resource loading, SDK sessions, fixtures, event subscriptions, registry, UI, snapshots, and cleanup. It uses `DefaultResourceLoader`, `createAgentSession`, `AgentSession.abort`, child-only `tool_call` interception, `parseSkillBlock`, and `session_shutdown` from Pi 0.82.1.

Each child uses a package-only `ima-pi-probe` skill loader with extensions otherwise disabled. Evidence distinguishes skill availability, an observed explicit load, and `useNotProvable: true`; it never infers semantic skill use. Structured snapshots (`IMA_PI_CONTROL_RESULT`, absolute path) omit raw prompts, commands, tool output, transcripts, credentials, and provider errors. Observability requires at least one configured sink: the compact UI and optional result file are attempted independently; partial sink failure is a sanitized degraded warning, while no configured sink or failure of every configured sink blocks startup/cancellation before model work.

Safety hooks allow ordinary work and block only direct recursive/forced deletion and destructive Git reset/clean/force-push forms. Child b receives three separate direct commands against a spike-created delete directory and committed-but-dirty disposable Git fixture, plus a harmless-marker command. A run can pass only after both blocks are observed and inspection confirms delete-sentinel preservation, exact Git HEAD/dirty-baseline preservation, and harmless-marker creation. Hooks are child-scoped and are not a shell parser or general permission system. Quoted, compound, obfuscated, aliased, and generated commands are explicit limitations; no remote is contacted.

## Verification and live procedure

```bash
node --test tests/control.test.js
npm test
git diff --check
git status --short
```

For live TUI acceptance, choose configured models with capacity, start a run, wait for child `a` to be active, then cancel it by exact run ID. Confirm concurrent event evidence, terminal usability, explicit skill loading, marker-based partial-state reporting, blocked disposable deletion/Git, unchanged sentinels, and harmless `pwd`. Provider auth/quota failure blocks only live acceptance and must be reported honestly—never replaced by fallback.

## Deferrals

No production registry, workflow engine, routing tiers, retries, persistent telemetry, permission matrix, keyboard cancellation, full shell parsing, or changes to FNR-3009, package metadata, `ima-goose`, or `ima-claude` are included.
