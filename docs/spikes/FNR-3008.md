# FNR-3008: Pi package and discovery conventions

## Decision

Use Pi's native package manifest and keep the preferred colon namespace:

```text
/ima:plan
/ima:implement
/ima:review
```

Do not build a command router or replace `:` with `-`. Current Pi accepts `:` in extension command names and prompt filenames, executes the command, and exposes both forms through its canonical command catalog used by command discovery.

## Package layout

Use Pi's conventional package resources and declare them explicitly in `package.json`:

```text
ima-pi/
├── extensions/
├── prompts/
├── skills/
└── package.json
```

Future first-class IMA agents and policies are package-owned data consumed by an extension; they are not native Pi resource types.

## Evidence

Validated against `@earendil-works/pi-coding-agent` 0.82.1 on 2026-07-29. The pinned development dependency defines the tested contract; changing that dependency requires rerunning this spike evidence.

Automated checks prove that:

- `/ima:probe package` executes as an extension command without a provider request.
- `pi.getCommands()` reports `ima:probe` as an extension command.
- `pi.getCommands()` reports `ima:prompt` as a package prompt command.
- `pi.getCommands()` reports `skill:ima-pi-probe` as a package skill command.
- A package extension, user extension, and trusted project extension are discovered together with correct `sourceInfo` provenance.
- Same-name `ima:prompt` collisions select the user prompt over the package prompt, then the trusted project prompt over both; each case asserts exactly one command and the winning `sourceInfo`.

## Native precedence

Pi's current resource loader sorts name-collision candidates from highest to lowest precedence:

1. Project setting entry
2. Project auto-discovered resource
3. User setting entry
4. User auto-discovered resource
5. Package resource

This is the desired project-first behavior. The automated same-name prompt collision test makes both user-over-package and project-over-user/package selection executable evidence. The order is implemented by Pi's `resourcePrecedenceRank()` and is evidence for using native loading rather than an IMA resource framework.

Collision behavior is resource-specific:

- Prompt, skill, and theme name collisions are first-wins after precedence sorting and produce diagnostics.
- Duplicate extension commands are retained and receive numeric invocation suffixes in load order, such as `/review:1` and `/review:2`.
- The same package configured globally and locally is deduplicated by package identity; the project package entry wins.
- Project resources load only after project trust. Non-interactive acceptance uses `--approve`.

First-class IMA agent definitions will intentionally use the same simple resolution policy:

```text
project-local → user-local → package
```

That agent resolution belongs to the later agent-discovery implementation. It should not alter Pi's native resource loading.
